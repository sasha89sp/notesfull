# Рост проекта до ~200 000 строк и перенос между чатами

## Размеры
- Файл: 200–400 строк (до 500–600 для цельного экрана/парсера). Меньше 50 строк — объединять. Резать по смыслу, не по счётчику.
- Всё проект целиком не прочитать (200 тыс. строк ≈ 3 млн токенов): работать через карту, читать только нужные 3–6 файлов.

## Что уже есть
- В первой строке каждого файла lib/ — комментарий `// ▸ описание` (части `_N.dart` помечены «Часть X»).
- docs/CODEMAP.md (генерируется `python3 tools/codemap.py` из tools/file_notes.txt), HANDOFF, DECISIONS, ROADMAP, SETTINGS, ARCHITECTURE.
- Новый файл: сразу добавить строку в tools/file_notes.txt и комментарий `// ▸ …` первой строкой.

## Что сделать при росте (ROADMAP)
1. Перед крупным новым модулем (или когда файлов в lib/ > ~200) перенести код в папки: lib/core, lib/notes, lib/calendar, lib/sync, lib/pass, lib/shared, lib/ui, lib/platform. Только после зелёного CI. Шаги: перенос скриптом с перепиской относительных import/part/part of; обновить tests/, variants/ (local_tx.dart, winsys.dart копируются в lib/ в CI — пути в build.yml!), ci/*.py, tools/*.
2. README.md в каждой папке модуля: что внутри, от чего зависит, точки входа.
3. Тесты на модуль; зависимости между модулями только через core.
4. Классы из одних статических методов и extension на публичные классы: помнить правила из DECISIONS («Ошибки CI после нарезки»).
